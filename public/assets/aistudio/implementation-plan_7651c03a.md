# Habits — план реализации

Один чат делает один шаг. Следующий шаг не начинается в том же чате.

Сообщение для нового чата:

```text
Реализуй шаг N из docs/implementation-plan.md.
Только этот шаг. Прочитай «Контекст для каждого чата» и правила, которые шаг перечисляет.
Если правило и этот файл расходятся, побеждает .cursor/rules.
```

После шага отметь его статус внизу этого файла: `не начат` → `готов`.

## Контекст для каждого чата

Приложение — локальный трекер привычек и дел: история, аналитика, графики. Исходники сегодня — шаблон GAS, кодек снимка, IndexedDB, клиент SolidJS со входом и экранами Сегодня / привычки / дела / история, и синхронизация одного файла Drive от имени вошедшего пользователя. `src/index.ts` экспортирует `main`, `doGet`, `downloadSnapshot` и `uploadSnapshot`. Базу открывает `HabitDatabase` в `src/db/habit-database.ts`.

Рабочая копия живёт в IndexedDB обычными записями. Google Drive хранит один упакованный снимок всех доменных записей, без которых другое устройство не восстановит трекер. Гость после загрузки HTML сервер не вызывает.

Слои, которые создаются по мере надобности. Пустые папки не добавлять.

| Путь            | Роль                                                                                       |
| --------------- | ------------------------------------------------------------------------------------------ |
| `src/index.ts`  | Точки входа GAS. Без логики привычек и без Drive.                                          |
| `src/types/`    | Интерфейсы и enum. Без поведения. `src/types/gas.types.ts` уже есть.                       |
| `src/utils/`    | Уже есть `Logger`, `Helpers`, `CivilCalendar`, `StreakCalculator`, `TodayBoard`, `TaskAnalytics`. Один файл — один класс. |
| `src/db/`       | IndexedDB. Единственное место, где вызывается `indexedDB.open`.                            |
| `src/sync/`     | Кодек и единственные вызовы Drive.                                                         |
| `src/auth/`     | Google или гость. Гость возвращается до Drive.                                             |
| `src/ui/`       | SolidJS. Читает и пишет `src/db/`.                                                         |
| `src/services/` | Обёртки Properties и Cache. Записи привычек туда не класть.                                |

Поведение — класс, и в файле он один. Записи домена остаются интерфейсами в `src/types/`. Вспомогательные шаги класса — его закрытые методы. Общие шаги без своего объекта — методы `Helpers`. Точки входа GAS остаются функциями и только вызывают класс. Компонент SolidJS остаётся функцией, а состояние и действия, которые он вызывает, живут в классе. Подробности — `.cursor/rules/15-oop.mdc`.

Инварианты:

- Отметка, правка, история и график пишут и читают только IndexedDB.
- День привычки — да или нет. В снимке это один бит. Число повторов и длительность в маску не входят.
- Имя, расписание, архив, заметка, дело и время правки входят в тот же снимок. Место экономится кодировкой: короткие id, номера дней, словарь строк, биты. Поле домена из снимка не выбрасывается.
- Серия, доля дней и точки графика в снимок не пишутся. Они считаются из записей.
- `doGet`, когда появится, возвращает только `HtmlOutput`.
- Клиент SolidJS не компилируется в серверный `dist/bundle.js`. `scripts/gas-plugin.mjs` копирует `src/**/*.html` в `dist/`.
- В `src/` `console.*` только внутри `src/utils/logger.ts`. Дальше `Logger`.
- Не вызывать `SpreadsheetApp`, `DocumentApp`, `SlidesApp`.
- Не редактировать `.env`, `.clasp.json`, `package.json`, пока шаг явно этого не просит.
- Не запускать `dev`, `watch`, `push`, `deploy`, `clasp:*`. Они отправляют проект в Google.
- Перед концом: `npm run typecheck` и `npm run lint`. Если менялись `src/` или `tests/`: `npm run test`.
- Тесты лежат в `tests/**/*.test.ts`, импорт `describe`, `it`, `expect` из `vitest`, как в `tests/helpers.test.ts`. `tsc` и ESLint тесты не видят.

### Домен, общий для всех шагов

День — целое `dayIndex`: число гражданских дней с `1970-01-01` по локальному году, месяцу и дню устройства. Это не UTC-метка. Бит привычки стоит на позиции `dayIndex - habit.startDay`.

Время правки — миллисекунды Unix, поле `updatedAt`.

| Запись      | Поля                                                                                                                          |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Привычка    | `id`, `name`, `color`, `weekdays` (7 бит, бит 0 — понедельник), `startDay`, `archivedAt` или `null`, `createdAt`, `updatedAt` |
| Отметка     | `habitId`, `dayIndex`, `done`, `updatedAt`                                                                                    |
| Заметка дня | `habitId`, `dayIndex`, `text`, `updatedAt`                                                                                    |
| Дело        | `id`, `title`, `note`, `dueDay` или `null`, `done`, `createdAt`, `updatedAt`                                                  |

`id` — целое с 1, стабильное между синхронизациями. Его назначает локальная база и хранит в записи. UUID в снимок не класть.

Серия считается по запланированным дням. День вне `weekdays` серию не рвёт. Доля — выполненные запланированные дни, делённые на запланированные дни периода.

Слияние двух устройств, для шага 7: у одной и той же отметки (`habitId` + `dayIndex`) и у одного и того же дела побеждает больший `updatedAt`. Остальные дни не затираются. Сломанный снимок базу не подменяет.

## Шаг 1. Типы, локальный день, серия

Статус: готов.

Прочитать: `.cursor/rules/10-typescript.mdc`, `.cursor/rules/50-tests.mdc`, `.cursor/rules/general.mdc`.

Сделать:

- Типы домена в `src/types/` по таблице выше. Без поведения.
- Класс `CivilCalendar`: из локальных год/месяц/день в `dayIndex` и обратно; сдвиг на N дней; бит дня недели.
- Класс `StreakCalculator`: серия и доля за период. На вход — привычка и список отметок. На выход — числа. База и Drive не нужны.
- Тесты в `tests/`: граница месяца, високосный день, день вне расписания не рвёт серию, пустой период, доля при нуле запланированных дней.

Не делать: IndexedDB, Solid, `doGet`, Drive, кодек.

Готово, когда `npm run test` покрывает день, серию и долю, а `typecheck` и `lint` проходят.

## Шаг 2. Кодек снимка

Статус: готов.

Прочитать: `.cursor/rules/30-sync.mdc`, `.cursor/rules/50-tests.mdc`, `.cursor/rules/01-architecture.mdc`.

Сделать:

- Класс `SnapshotCodec` в `src/sync/snapshot-codec.ts`. Рядом отдельные файлы для `StringTable`, `IdTable`, `SnapshotReader` и `SnapshotBytes`. `pack` принимает полный домен и возвращает байты. `unpack` возвращает те же записи.
- Отметки — битовая маска от `startDay`. Повторяющиеся id и строки — словарь. Текст заметок и дел — в том же снимке, вне битового поля.
- Серии и графики в байты не входят.
- Тест: привычка, месяц отметок, заметка и дело упаковываются и распаковываются в те же поля. Отдельный тест на пустой домен и на битую последовательность байт: `unpack` бросает, вызывающий код базу не трогает. Вызова `DriveApp` в тесте нет.

Не делать: загрузку в Drive, IndexedDB, экран.

Готово, когда круг pack → unpack сохраняет каждое поле домена.

## Шаг 3. IndexedDB

Статус: готов.

Прочитать: `.cursor/rules/20-local-store.mdc`, `.cursor/rules/01-architecture.mdc`, `.cursor/rules/15-oop.mdc`.

Сделать:

- Класс в `src/db/` открывает базу. Снаружи — его методы: привычки, отметки, заметки, дела.
- Отметка хранится записью, которую можно поставить и снять. Маска в базе не лежит.
- Индексы по привычке и по дню.
- `id` выдаётся из базы и больше не меняется.

Не делать: вызов Drive, импорт `src/sync/` из пути отметки, `localStorage`, Properties, Cache. Экраны не писать. Браузерный тест IndexedDB не требуется: раннер Vitest — Node (`.cursor/rules/50-tests.mdc`).

Готово, когда отметка пишет одну запись и возвращается, а открытие базы есть только в `src/db/`.

## Шаг 4. Оболочка клиента и вход

Статус: готов.

Прочитать: `.cursor/rules/40-ui.mdc`, `.cursor/rules/01-architecture.mdc`, `.cursor/rules/60-security.mdc`, `.cursor/rules/15-oop.mdc`.

Этот шаг меняет `package.json`: добавить SolidJS. В первом сообщении чата должно быть явное разрешение править `package.json`. Без этой фразы шаг не начинать.

Сделать:

- Клиент SolidJS в `src/ui/`, без React и без SolidStart.
- Сборка клиента отдельно от серверного `dist/bundle.js`. HTML из `src/` попадает в `dist/` существующим копированием `scripts/gas-plugin.mjs`.
- `doGet` в `src/index.ts` остаётся функцией, возвращает `HtmlOutput` и больше ничего. Список привычек из `doGet` не отдаётся. Сама сборка ответа — метод класса.
- Первый экран: Google или гость. Выбор хранит класс сессии. Гость открывает трекер. Кнопки, которая зовёт сервер, у гостя нет.
- Ответ сервера без email, user id и OAuth-токена.

Не делать: синхронизацию, графики, вызов Drive. `dev` и `push` не запускать.

Готово, когда страница открывает выбор входа, а гость остаётся на клиенте.

Статус: готов.

Прочитать: `.cursor/rules/40-ui.mdc`, `.cursor/rules/20-local-store.mdc`, `.cursor/rules/15-oop.mdc`.

Сделать:

- Экраны списка: создать, переименовать, сменить дни недели и цвет, архивировать привычку. Архив убирает её из «Сегодня» и оставляет отметки.

Готово, когда отметка и дело сохраняются локально и видны после обновления страницы без сервера.

## Шаг 6. История и аналитика

Статус: готов.

Прочитать: `.cursor/rules/40-ui.mdc`, `.cursor/rules/20-local-store.mdc`, `.cursor/rules/50-tests.mdc`.

Сделать:

- Месяц по `dayIndex`. Прошлый день можно отметить или снять той же записью, что и «Сегодня».
- На экране: текущая серия, самая длинная серия, доля за выбранный период, тепловая карта отметок, число закрытых дел по неделям.
- Цифры берутся из `StreakCalculator` и из записей `src/db/`. В базу и в снимок они не сохраняются. Дела по неделям считает отдельный метод класса, не свободная функция.
- Пустая база показывает пустой период, без подставных точек.

Не делать: отдельный серверный метод для графика, чтение Drive.

Готово, когда история и графики совпадают с локальными отметками, включая день вне расписания.

## Шаг 7. Снимок Google Drive

Статус: готов.

Прочитать: `.cursor/rules/30-sync.mdc`, `.cursor/rules/60-security.mdc`, `.cursor/rules/90-anti-patterns.mdc`, `.cursor/rules/01-architecture.mdc`, `.cursor/rules/15-oop.mdc`.

Сделать:

- Google может синхронизировать. Гость до Drive не доходит: нет scope, нет файла, нет вызова.
- Класс синхронизации пакует полный домен через `SnapshotCodec`. Одинаковые байты повторно не заливаются. Пачка правок сходится в одну загрузку.
- Класс на сервере читает и пишет один файл. Каждый вызов Drive идёт через `Helpers.withRetry` из `src/utils/helpers.ts`. `src/index.ts` только экспортирует функцию, которая вызывает этот класс.
- Скачивание распаковывается в памяти. Запись в IndexedDB начинается после успешного `unpack` и слияния по `updatedAt` из раздела «Домен».
- Ошибка сети, пустой файл и битые байты оставляют локальную базу как есть.
- В лог и в ответ не попадают токен, email и script id.

Не делать: файл на каждую отметку, JSON-дамп IndexedDB, снимок только из битов без имён и дел.

Готово, когда второе устройство восстанавливает привычки, отметки, заметки и дела из одного файла, а сбой скачивания локальные данные не стирает.
